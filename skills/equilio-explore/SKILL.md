# Explore

Establish the current problem and available context from the issue, local Markdown, prototype, or code. Name the assumption or decision that exploration could change. Choose a small number of meaningfully different options; do not produce variations merely for volume.

Prototype in the running product when feasible, using the lightest reversible change that exposes actual behavior and experience. Observe rather than infer how each option affects users, design, UX, and implementation. When a running prototype is impractical, state the constraint and use the closest useful evidence. Keep observations, tradeoffs, and decisions in local Markdown so the user can inspect them.

Choose a direction when evidence supports one; otherwise identify the next discriminating test. Update the project's GitHub, Linear, or local Markdown issue with accepted findings and the reason for the choice, after establishing its destination. Summarize; do not paste a transcript or the entire working file. Leave the problem, options, chosen path, and remaining uncertainty clear enough for a teammate or a new agent session to continue.
