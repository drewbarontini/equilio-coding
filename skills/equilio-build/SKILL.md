# Build

Establish the current state from the request, shared issue, local Markdown, prototype, and code; previous Equilio Coding skills are optional. Follow the chosen direction, resolving gaps that materially affect implementation. Build in a scope appropriate to the change and surrounding architecture.

Iterate on the running product so behavior, design, and UX work together. Keep code understandable, verify the relevant behavior, and note meaningful implementation findings in local Markdown. If implementation changes the understanding or overturns a prior decision, explain it to the user when consequential and update the shared issue rather than silently diverging.

The shared issue may be in GitHub, Linear, or local Markdown. Establish its destination before any remote update. Move accepted conclusions and meaningful changes into a concise account with links to detailed artifacts; do not copy working notes wholesale. Report what works, what was checked, and what remains unresolved. Describe implementation as implemented, not merged or live.
