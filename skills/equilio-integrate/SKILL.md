# Integrate

Start with the available issue, local Markdown, code, PR, or deployed result; the earlier skills need not have run. Check coherence across the product experience, code structure, and strategic purpose. Run checks proportionate to the change and inspect the result in the running product when feasible. Record findings and any refinements in local Markdown.

Update diagrams and durable documentation when the system actually changed and those artifacts will help future work. Prepare a short PR for a human reviewer using **Summary**, optional **Callouts**, and **Context** linking the source issue. Summary should say what changed and how it was verified in two or three plain-language sentences; call out only decisions or behavior needing reviewer attention. Use issue-closing syntax where the tracker supports it.

The issue is the full lifecycle account, in GitHub, Linear, or local Markdown. Establish its destination before any remote update. Refine its narrative and link to code, diagrams, durable docs, PR, and release as available. Complete its final outcome and release observations after the change is actually merged and live. Distinguish implemented, merged, deployed, and verified live; never claim a later state without evidence. Leave remaining signals visible.
