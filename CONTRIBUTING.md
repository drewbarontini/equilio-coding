# Contributing

Keep Equilio Coding small and usable across projects and issue systems.

- Keep five standalone workflow skills: `equilio-frame`, `equilio-map`, `equilio-explore`, `equilio-build`, and `equilio-integrate`. Each needs valid `name` and `description` frontmatter, a distinct trigger, one primary job, and a useful output. Each must work when installed alone and entered from a rough request, an issue, a local file, a prototype, or code.
- Keep `equilio-loop` as one optional orchestration skill, used with all five workflow skills. Loop accepts a goal, establishes or reuses the right issue, coordinates the current canonical skill instructions, and stops at coherent, verified, review-ready work by default. It is not a sixth workflow stage and must not duplicate the five skills' judgment or methods.
- Preserve the issue as canonical current understanding and shared memory across Loop transitions, readable by humans and AI without prior conversation. Every skill must re-read and rewrite it before finishing; Loop must re-read it at each transition. Write-back is synthesis: replace stale claims, consolidate overlap, and keep material learning and decisions; do not append a stage log.
- Keep local Markdown available for detailed working notes. Preserve the **Working Notes → Issue → PR** distinction: synthesize understanding into the issue and put patch-specific implementation detail in the PR. Establish a remote destination before changing it. Keep conventions consistent with [the issue reference](references/issue.md) and [PR template](.github/pull_request_template.md). Do not add a stage gate, service dependency, or automation without a demonstrated need.
- Preserve the shared [Development Principles](references/development-principles.md) across the five skills and Loop. Link to the reference instead of repeating it; keep its guidance proportionate and leave room for judgment. A small coherent change may still cross every layer required for functioning software.
- Let Loop re-enter earlier skills when material evidence changes their judgment. It should continue autonomously through reasonable choices and ask for human judgment only when a consequential decision lacks a sound basis. Do not add approval gates between skills. Merge, release, and deployment require explicit authorization.
- State what is observed, decided, implemented, merged, deployed, and verified live accurately. Keep the five steps distinct from Equilio's three Models.

Before proposing a change, validate modified skills with the skill validator, list the repository through `npx skills add <local-path> --list` when the CLI is available, and confirm that a single workflow skill and Loop can each be selected with `--skill <name>`. Read the README and example against the actual skill instructions.
